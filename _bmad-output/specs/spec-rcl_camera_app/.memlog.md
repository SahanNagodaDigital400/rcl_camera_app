- (capability) CAP-1 Auth & Session Management. Intent: Staff/Admin authenticate only via Administrator-provisioned accounts, sessions persist safely through a shift, end immediately on deactivation. Success: temp credential reaches only password-change screen until replaced, expires unclaimed after 72h; session token lives only in HTTP-only/Secure/SameSite=Strict cookie; deactivated user's live session rejected on the very next request, not next login. From PRD FR-1-5.
- (capability) CAP-2 Tile Scanning & Identification. Intent: Staff/Admin capture or upload a tile photo, crop to just the tile face, get up to three visually-ranked candidate matches to confirm by sight. Success: submitted Scan is always the cropped region; materially blurry cropped region prompts retake before submission; results always show up to three Candidates with image+code+size+design, never a single unverifiable answer; crop-confirmation-to-result under 3s. From PRD FR-6,7,8,9,24.
- (capability) CAP-3 Admin User Management. Intent: Administrator manages the Staff/Administrator population entirely in-app -- create, edit, deactivate, delete. Success: a role edit or deactivation takes effect on the user's very next request, not next login; the last remaining active Administrator account cannot be deactivated or deleted. From PRD FR-10-13.
- (capability) CAP-4 Admin Catalogue Management. Intent: Administrator adds, edits, removes, or bulk-loads Products and Reference Images directly, Catalogue searchable immediately, no developer/re-import needed. Success: a Product added mid-session is returned as a Candidate for a Scan submitted later that same session; bulk upload reports per-row success/failure; a removed Product/Reference Image never resurfaces as a Candidate. From PRD FR-14-19.
- (capability) CAP-5 Audit Log & Anomaly/Rate-Limit Defense. Intent: every account and Catalogue change is immutably logged and viewable by Administrators; login and scan activity rate-limited, anomalies flagged. Success: no update/delete path exists against the audit log at the application or database-role level; a scan burst is throttled independent of whether it also triggers an anomaly flag. From PRD FR-20-23.
- (constraint) Local auth only, no SSO/external IdP -- Rocell has none (PRD OQ-6, resolved). Admin-provisioned accounts only, no self-registration.
- (constraint) Server-side authorization on every privileged request, independent of what the UI hides (AGENTS.md Policy).
- (constraint) General staff rollout gated on an independent penetration test passing -- app is the sole gatekeeper to Rocell's full catalogue and staff account list.
- (constraint) Two roles only in v1 (Staff, Administrator); at least two active Administrator accounts must exist at all times.
- (constraint) Every image (Scan or Reference Image) is content-validated, re-encoded, and EXIF-stripped before storage -- never trusted by file extension.
- (constraint) Full architecture-level invariants (index/query preprocessing symmetry, session/audit/crop mechanisms, stack, dependency rules) are binding via the adopted ARCHITECTURE-SPINE.md companion -- not restated in the kernel.

- (note) Non-goals (from PRD S9/S10.2): no native iOS/Android app; no offline scanning; no identifying already-installed tiles; no price/stock/spec data; no customer/dealer access in v1; no app-sent email; no ERP/POS/inventory integration; no maintained size+design-to-code mapping table (Code is the Reference Image's cleaned file name); no confidence-gated single-answer result (always up to 3 Candidates); no crop step for admin-added Reference Images (explicitly resolved during architecture Update, not deferred).
- (note) Success signal (from PRD S11 SM-1..SM-6, SM-C1): Phase 2 pilot sets concrete top-3 (SM-1) and top-1 (SM-6) accuracy targets; crop-confirmation-to-result stays under 3s (SM-2).
