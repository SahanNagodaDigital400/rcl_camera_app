- (decision) AD-13 [ADOPTED, from POC]: Reference embeddings are multi-vector, not one-vector-per-image. Each Reference Image contributes up to 16 embeddings (4 clean rotations + 12 randomized augmented crops, scale 25-60%, carrying lighting/WB/blur/perspective/JPEG augmentation) stored in a child REFERENCE_EMBEDDING table (FK to REFERENCE_IMAGE), never pooled into a single vector at write time -- pooling would give back the scale-invariance the crops exist to buy. A Scan embeds exactly ONE view (full frame; POC measured a second query view scores worse and doubles latency) and is compared against every REFERENCE_EMBEDDING row for a candidate image, taking the MAX similarity across that image's views (max-pool at search/query time). Binds shared/vision, apps/api search path, scripts/ingest, ERD. Prevents a builder shipping REFERENCE_IMAGE as a single-vector row (my original ERD's mistake, called out explicitly by the POC as needing a decision before shared/vision is written).
- (decision) AD-14 [ADOPTED, from POC]: The index carries an explicit pipeline-version stamp (hash of shared/vision code + preprocessing config) on every embedding row; search refuses to run against a mismatched stamp rather than silently degrading. Binds shared/vision, apps/api search endpoint, scripts/ingest. Prevents AD-1's procedural-only enforcement ('state the reindex in the PR') from being the sole guard -- converts a process discipline a person can forget into a mechanical refusal.
- (decision) AD-15 [ADOPTED, from POC]: Color management is mandatory inside shared/vision's load_image, before any resize/crop/embed step -- transform any embedded ICC profile into sRGB at RELATIVE COLORIMETRIC intent (never perceptual, never with black-point compensation); missing profile assumes sRGB. Binds shared/vision. Prevents the exact bug POC found: ~60% of this catalogue is CMYK press files: naive .convert('RGB') discards the profile and shifted one tile's channel by up to 84.6 levels, rendering it a completely wrong color AND poisoning its embedding with wrong pixels -- a systematic domain gap the pipeline itself introduces, distinct from and worse than AD-2's studio-vs-phone gap. Validated by a dedicated brightness+hue test (a hue-only fix can still be badly wrong on brightness, as POC found).
- (decision) AD-16 [ADOPTED, from POC]: Embedding inference is serialized -- one scan's model forward-pass at a time server-side, independent of AD-8's per-user abuse-defense rate limiting. The ONNX session is created once at server startup (warmed, not per-request; session creation costs ~900ms) behind an init lock (prevents two concurrent first-scans racing to each build a session). Binds apps/api scan endpoint, shared/vision inference call site. Prevents the exact collapse POC measured: 8 concurrent CPU-bound ONNX inferences run 12x slower each (206ms -> 2.6s) because each request's threads oversubscribe the available cores -- a correctness/performance invariant, not a security one, that a naive 'handle requests concurrently' web-server default would violate.
- (decision) AD-17 [ADOPTED, from POC]: Reference images are served to the client from a pre-generated, capped-size derivative (POC: 1280px, ~300KB budget) created at catalogue-write time (add/edit/bulk-load) -- never the original asset, never generated on-demand at read time. Binds apps/api catalogue read path, shared/vision or a catalogue-write hook. Prevents the exact bug POC found: building a reference view on demand means decoding an original up to 96MB, measured at 1-3.5s per tap -- serving FR-7's required reference image would silently violate the product's speed expectations even though matching itself stays under the 3s budget.
